# Aviasales Flight Search

## Что делает
Находит лучшие (минимум суммарной цены в ₽) варианты перелётов, в т.ч. сложные
мультигород-маршруты. Пользователь описывает поездку словами — ты собираешь
`trip.json` и запускаешь CLI. CLI ходит в реальный внутренний API aviasales.ru
(двух-хостовый флоу `start` → `results`): вся поездка (все направления сразу)
ищется ОДНИМ запросом, авторизуясь куки/заголовками из cURL, скопированного
из браузера пользователя (тело запроса CLI строит сам). Результаты кэшируются
и рендерятся в Markdown-отчёт.

## Рабочий процесс

1. **Собери ограничения у пользователя** (по одному вопросу, если чего-то нет):
   маршрут (направления), окна дат для каждого направления, пассажиры, класс,
   и ЖЁСТКИЕ фильтры (макс. пересадок, макс. время стыковки, макс. длительность
   перелёта, багаж да/нет, время суток вылета/прилёта, исключить пересадки
   через Персидский залив и/или конкретные аэропорты). Фильтры не
   оптимизируются — оптимизируется только суммарная цена в ₽.

2. **Составь `trip.json`** по схеме (см. `README.md` в корне плагина →
   «Схема конфига»).
   Ключевое:
   - `directions` — список ВСЕЙ поездки целиком (туда-обратно или мультигород
     — несколько записей в одном списке, не отдельные one-way запросы).
     Каждая запись: `from`, `to`, обязательное `date_window: {earliest,
     latest}` (Claude вычисляет окна дат из NL пользователя, например «2
     недели в Стамбуле» → окно дат вылета следующего направления), опционально
     `constraints`, переопределяющие `global_constraints` для этого
     направления.
   - `global_constraints` — дефолтные жёсткие фильтры на все направления:
     `max_transfers`, `max_transfer_minutes`, `baggage_required`,
     `max_duration_minutes`, `depart_time_of_day`/`arrive_time_of_day`
     (`morning|afternoon|evening|night`), `exclude_gulf_transfers: true`
     (исключить пересадки через Персидский залив) или явный
     `exclude_transfer_airports`.
   - `max_trip_days` (опционально, верхний уровень) — макс. число дней между
     датой вылета первого направления и датой вылета последнего («вся поездка
     не дольше N дней»).
   - `passengers`, `trip_class`, `currency`, `market_code`.
   - `search_budget.max_requests` (деф. 100) и `date_samples_per_direction`
     (деф. 10) — верхний предел реальных сетевых запросов и плотность сетки
     дат (кэш-хиты бесплатны); понижай при риске бот-блокировки.

3. **Убедись, что есть свежий `curl.txt`.** Если его нет или CLI ранее вернул
   код 2 (протух/забанен) — дай пользователю инструкцию из раздела
   «Обновление cURL» ниже и дождись файла.

4. **Запусти CLI.** Python-проект (файл `pyproject.toml` со скриптом
   `aviasales-search` и пакет `aviasales_search`) лежит в корне плагина —
   в установленном плагине это `${CLAUDE_PLUGIN_ROOT}`. Рабочие файлы
   (`trip.json`, `curl.txt`, `report.md`) держи в текущей рабочей директории
   пользователя, а проект укажи флагом `--project`:
   ```
   uv run --project "${CLAUDE_PLUGIN_ROOT}" aviasales-search --config trip.json --curl curl.txt --out report.md
   ```
   Если переменная `CLAUDE_PLUGIN_ROOT` не задана (скилл запущен прямо из
   репозитория, а не из установленного плагина), подставь вместо неё корень
   репозитория. Требуется установленный `uv` — если его нет, попроси
   пользователя установить (https://docs.astral.sh/uv/).
   Полезные флаги: `--top N` (больше вариантов, деф. 10), `--refresh` (искать
   заново, игнорируя кэш), `--max-requests M` (шире перебор дат).

5. **Обработай результат:**
   - Код 0 → покажи `report.md` пользователю.
   - Код 2 → cURL протух или сработала защита от ботов: попроси обновить
     (раздел ниже), затем повтори запуск.
   - Код 1 → ошибка конфига: почини `trip.json` по сообщению об ошибке и
     повтори.

6. **Кэш.** По умолчанию зонды переиспользуются `cache.ttl_minutes` минут (по
   умолчанию 5; легаси `ttl_hours` тоже принимается) — сеть не дёргается
   лишний раз. Если пользователь просит
   «поищи заново» — добавь `--refresh`. Снапшоты прогонов лежат в
   `~/.aviasales-cache/runs/<дата-время>/`; при повторном прогоне того же
   маршрута отчёт покажет дельту к прошлой лучшей цене.

## Обновление cURL (объясни пользователю по шагам)

cURL — это ТОЛЬКО авторизация: куки и заголовки браузера, включая
`x-aws-waf-token`. Тело запроса CLI конструирует сам из `trip.json`, поэтому
подходит **любой** запрос к `tickets-api…aviasales.ru`, скопированный как
cURL, — искать именно запрос старта поиска не нужно:
1. Открой https://www.aviasales.ru в Chrome.
2. Нажми F12 → вкладка **Network** → впиши в фильтр `aviasales`.
3. Выполни любой простой поиск (например, Москва → Санкт-Петербург), чтобы
   в списке запросов появились нужные.
4. Правый клик по ЛЮБОМУ запросу к `tickets-api...aviasales.ru` → **Copy** →
   **Copy as cURL (bash)**.
5. Вставь ассистенту или сохрани в файл `curl.txt` в текущей рабочей
   директории.

## Важные замечания
- Поиск идёт с IP пользователя и его куки. У aviasales есть бот-защита
  (WAF + botScoring + невидимая smartCaptcha) — держи объём запросов
  небольшим, не увеличивай `--max-requests` без необходимости; между
  сетевыми вызовами уже встроены человекоподобные паузы. При HTTP 403/429
  или капче в ответе CLI сам остановится с кодом 2 — в этом случае нужен
  свежий `curl.txt` (см. выше), а не повтор с теми же куками.
- **Безопасность/секреты:** `curl.txt` содержит живые куки/токены сессии
  пользователя (ключ доступа к его сессии на aviasales.ru). Никогда не
  предлагай закоммитить `curl.txt`/`curls.txt`, а также `trip.json` и
  `report.md` (личные данные о планах поездки) — все они в `.gitignore`.
- Если Aviasales поменяет схему ответа `/results`, править нужно только
  `extract_tickets` в `aviasales_search/results_parser.py` (см. README →
  «Живой прогон»).
